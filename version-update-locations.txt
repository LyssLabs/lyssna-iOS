Lyssna version updates
======================

Use one semantic version, currently 0.1.3. No separate Lyssna build number.
Keep the package, runtime, and installer metadata versions aligned when updating the app.

Keep these current values aligned:
- control: package Version
- Sources/Lyssna/Tweak.x.swift: runtime version shown in settings and logs
- NativeDownloads/targets/spotify-9.2.0.json: lyssna_version
- NativeDownloads/src/Generated/BuildIdentity.h: diagnostic version labels
- NativeDownloads/tools/port/make_profile.py: version used for new profiles
- README.md: source version and example output filename
- .github/workflows/native-downloads.yml: optional input description

Historical provenance records describe their original upstream builds and keep
those original version values. Packaging writes the Lyssna version from control
to both CFBundleShortVersionString and CFBundleVersion for the app and extensions.
Native Spotify values remain in LyssnaSpotifyVersion and LyssnaSpotifyBundleVersion
for hook selection, native configuration, diagnostics, and compatibility checks.

build-ipa-local.sh reads the Lyssna version from control and the Spotify version
from the source IPA. Finished files use Lyssna-<version>-<spotify-version>.ipa.
